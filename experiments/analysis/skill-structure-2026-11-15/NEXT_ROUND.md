# 下一轮：内容、图型与路由分别消融

状态：设计草案，尚未生成新材料或启动模型任务。以下预算、阈值和停止规则必须在看见新结果前登记；本轮旧任务只能作为开发／机制集，不是未知测试集。

## 1. 假设与能否被否定

|假设|主要对比|支持它的结果|会否定／缩小它的结果|
|H1 提炼内容有用|S 对 T|质量不降低，约束／单位错误减少或效率提高|没有改善；或摘要遗漏关键条件|
|H2 视觉布局有额外价值|U 对 S；F 对 S|同语义内容下有质量／效率增益|S 与图片相当或更好，则优先用文字|
|H3 结构匹配比统一图更好|F 对 U|预定结构相关错误减少，且任务质量不降|只有个别任务偶然节省，或收益无法重复|
|H4 关系结构匹配本身重要|F 对 X|保持相同内容／预算，匹配图更好|两种布局同样有效，说明更可能是标签突出或摘要作用|
|H5 拒绝画图和多面板有价值|A 对 F|短／混合 skill 上质量不降、资源减少|面板变多而错误未减，或拒绝画图损害表现|

U/F/X 的比较才是图型选择实验；旧 v1/v2 比较不能代替它。H2 更准确地测“同内容的视觉布局／编码包”的效果，不声称分离了所有字体、空间和模态因素。

## 2. 六个实验组

所有组给相同完整本地 skill 包、GUIDE 和任务可见输入，使用同一模型路由、Agent 版本、预算和工具。为接续现有实验，主实验继续固定每个任务请求注入；按需查看图是后续独立实验。

|组|新增内容|与谁比较、隔离什么|
|---|---|---|
|T|无|全文基线，必须在本轮重跑，不能复用旧文字样本|
|S|共同语义表示 IR 的紧凑文字／表格|S−T：内容提炼的作用|
|U|同一 IR 渲染为统一活动流程图|U−S：统一视觉编码；U 是新冻结的同内容控制，不复用旧图|
|F|同一 IR，使用人工源结构标注选出的表示|F−U：结构匹配；F−S：匹配图对文字|
|X|同一 IR，预先指定的不匹配布局|F−X：关系结构是否重要|
|A|完整路由策略：允许拒绝画图、主图＋最多一辅图|A−F：拒绝与组合策略的整体作用；不能单独归因于拒绝或面板数量|

X 是布局负对照，不制造假算法。例：缓存内容改用数据流卡片，数据契约改用时间线卡片，递推内容改用策略表，窗口约束改用活动布局。映射在生成前固定，不按结果选择最差图。各关系仍显式保留类型／标签；不能把非顺序关系强画成不存在的因果或时序边。若某 IR 无法在所指定布局中忠实表达，登记为材料不可行，修订整个对应配对的材料并在运行前重新冻结；不能用错误事实人为制造 X 失败。

F 用人工审查的结构标注，先检验路由假设。自动特征抽取作为后续单独消融：人工特征 F 与自动特征 F_auto，图型与渲染保持一致；不要在本轮把特征抽取质量也一起改变。

另设 **P：朴素统一 prompt**，用固定的“阅读完整 skill，将其整理成 UML 并渲染”模板、相同源闭包、同一生成模型与生成预算生成新图，再和全文一起交付。保存 prompt、响应、失败重试、生成成本和渲染检查。P 与 A 比较回答整体方法是否值得替换，内容和图型可能同时变化，不能单独归因于选图。现有本地 UML 是逐 skill 定制的固定字符串，不可拿它们冒充 P。

## 3. 先固定内容，防止换图时偷偷多给知识

1. 来源限制为完整本地 skill 闭包。记录 SKILL、脚本、参考、显式兄弟依赖、共享资源及哈希。不得从 oracle、verifier、历史 agent 代码或旧分数补全生成内容。分析报告中的评分失败只用于定义事后诊断类别，不作为通用 skill 新知识。
2. 建立共同 IR：每个 atom／relation 有 ID、精确来源行段、实体、关系类型、guard、units、前提、索引方向、歧义标记。未在源中给出的内容标“未提供”，不由制图器补算法。公式、branch、guard、脚本输入／返回、边界约束均进入覆盖核对。
3. S/U/F/X 使用完全相同的 IR atom、公式、条件和标签；渲染器不再调用 LLM 重写摘要。U 中不适合流程的关系保留在带类型的说明卡里，不用虚假的“下一步”箭头。IR 保真优先于图面整齐。
4. U/F/X 固定每 skill 同一标签预算、同一可用画布面积、同一最小可读字体和同一逻辑画布数量。先在开发材料确定可读阈值并登记，再冻结测试材料。若长图需要拆分，各组按相同预算重排；不能只给 F 更清晰的字号或更多页面。
5. 记录渲染器版本、PNG 尺寸、实际标签字号、字数、注入次数、可见输入次序、材料哈希与全部生成调用成本。PNG 面积不代替图片 token；供应商不报告时明确缺失，不估造成真值。
6. 人工检查来源覆盖、未授权新关系、公式／单位、状态迁移、索引顺序与输出契约，且不看即将评分的隐藏测试。可先做小型读图问答检查关键标签／关系，作为材料预检，不混入任务成绩。

当前 skill 是组合处理。S/U/F/X 全任务比较仍不能估计每个单 skill 的贡献。要定位，后续在固定 task 的基线上逐一替换一个 skill 的表示，其他保持相同，或为单 skill 构造独立理解测验；不把同时替换四张图的收益平均分给四个 skill。

## 4. 样本、顺序和运行预算

主机制集保留缓存、电价、R2R、考试、制造五任务，六组，每组每任务六次新运行：**5×6×6=180 次计划运行**。六重复适合发现机制和较大差异，不足以承诺统计功效；不要把 180 次当作 180 个不同 skill。晶体若要复验，额外 36 次，预先单列。

为直接回答统一 prompt 的端到端问题，建议同时纳入 P 的 **5×6=30 次**，合计 **210 次**。七组采用 task×repeat 内随机排列，并约束全局位置／时段尽量均衡；下述六阶循环顺序仅适用于纯六组机制实验，七组不能原样套用它。

每任务用六种循环组别顺序：T S U F X A；S U F X A T；……；A T S U F X。六个重复随机对应这些顺序，保证每组在每个运行位置恰好一次；再将任务块在日期／时段间随机交错。顺序表与随机化种子先保存。若模型端不支持 seed，明确记为不可控，不虚构相同随机流。一次新运行一个容器／会话，不共享 agent 历史、生成代码或执行产物。

五任务重复是 task×repeat 区组；配对比较在区组内做，避免把每个模型请求当成独立样本。顺序和时段作为记录变量。固定并记录实际 provider／model ID、可用的采样参数、上下文策略、预算、缓存语义、OpenCode 与工具版本；服务端版本不可见时注明。

先做不调用任务模型的材料／传递检查和所有任务的 oracle/nop 健康检查，保证评分确实执行。沿用制造已记录的离线启动适配，记录其范围，测试断言不改。不要顺便给某一组加装额外 solver。

费用只给预算口径，不把旧估算当报价。当前 v2 十条共约 $0.438587，机械放大到 180 条约 **$7.89**；这仅是基于旧调用的量级锚点，不含生成、控制、失败重试、服务端价格变化或可能更长的轨迹。按旧 agent 执行总秒外推约 **24 小时串行 agent 时间**，尚不含环境与控制开销，不能当实际完工承诺。

若含 P 共 210 次，相同机械外推约 $9.21、28 小时串行 agent 时间；P 本身的图生成开销仍须额外计入。上述均为规划参考，不是运行报价或用量承诺。

## 5. 失败保留、完整性和执行控制

- 主指标使用所有预定槽位：超时、无产物和算法错误计入失败。原始记录永久保留。不得看到分数后只补跑失败组或选择得分更高的一次。
- 提前统一基础设施故障定义：鉴权、provider 连接失败、容器启动失败、评分依赖未执行测试、强制输入格式损坏等单独标记。预登记最多一次完整 task×repeat 六组区组补跑；全部原尝试成本计入，报告原始与替代口径的敏感性结果。若新故障再次发生，保留 missing／failed，不无限补到成功。
- 安装额外 solver、长时间求解和预算耗尽属于端到端执行选择，不能自动当作可排除的基础设施问题。工具集与依赖环境在各组一致，网络策略统一。外部检索若保留，完整记录；若改为离线资源，六组都使用同一新环境并单独标版本。
- 每次保存真实测试数、CTRF、reward、usage、task digest、全文／图片传递证据。超时的传递 valid=false 分别细分为“已捕获调用材料正确但运行不完整”与“请求缺图／哈希不符”，避免混淆。
- 统一启用可用的运行完整性检查；记录 hidden verifier／oracle 探测、成功访问和结果影响，预先定义违规后如何计分与补充分析。保留 native reward 和完整性标记两列，不能把原生通过写成 integrity 通过。所有诊断只做事后分析，生成与执行都不访问隐藏答案。

## 6. 指标与统计报告

**质量优先**：原生完整任务通过率、完整交付率、超时率、实际测试执行率。分项测试通过率只在同任务内比较：制造 15 项与电价 4 项的权重和难度不同，不能把所有测试合成一个大比例。

**机制指标**：来源 atom／relation 保留率、无来源断言数、状态／guard／索引错误数、单位或归一化错误数、指标定义不一致数、首次可行产物落盘时间、最终落盘文件的独立复算完成率、solver 安装／等待／搜索时间、实际引用本地图的证据。没有引用不能断言没用图；传递成功也不能断言已理解。

**效率**：input、cached input、uncached input、output、总 token、主／辅助调用、工具调用、agent wall time、provider wait、求解时间、框架估算费用。图／IR 生成的模型与渲染成本另列，报告首次使用总成本与固定复用次数下的摊销成本。超时用量不全时标下界／缺失，不插补成完整节省。

**结构相关诊断预登记**：

|结构|独立测验或诊断|对应候选表示|
|---|---|---|
|缓存状态|先计 prefix hit 后更新；G 不计驻留；promotion 保留频率；平局与容量边界|状态机＋事件顺序／策略表|
|数据和数值契约|ID 对齐、units、函数 I/O、约束方向与 dual；源歧义保留|schema／数据流／约束图|
|反馈和递推|k 与 k+1 顺序；积分 dt／泄漏／限幅；可见任务定义下的独立指标重算与重试|递推图／反馈框图／验证闭环|
|有序窗口|tuple 方向、mask、边界、后继与 active overlap；不能用未定义的组合替代|窗口对齐／约束图|
|局部修复|前序顺序、合法机台、停机半开区间、预算与最早可行边界|资源时间线＋不变量|
|交付审计|真实 incumbent、落盘重读、指标与文件一致、预算到期前交付|产物门控流程|

独立理解测验从 skill 源规则生成，开发／测试案例分离，各组回答同一批未见微案例；不要把本轮失败的具体输入或隐藏评分阈值写进图。可用于机制检查，不能替代 benchmark。

分别报告每任务每组的原始观测和均值／中位数／分布。效率使用区组内 log 比率，再在任务间等权汇总；另报总消耗加权结果，明确差异。只在同质量子集中报告的效率属于条件描述，同时保留全槽位质量与资源结果，防止幸存者偏差。

所有核心对比及先后顺序预登记，F−U 为主要图型对比，其余为机制探索；提供按任务聚类／区组配对的不确定性估计。只有五个任务簇时区间不稳定，须展示全部任务结果，不靠一个显著性数字宣称普遍有效。若六重复无法区分结论，标记未决，再用预先固定、独立的验证阶段增加样本，不能边跑边挑好结果。

## 7. 决策与下一阶段

建议在实验前协商并锁定质量非劣界和效率最小收益；可将“任务通过率不降低超过 5 个百分点、同质量成本／token 几何均值至少改善 10%”作为设计目标，但当前 5×6 样本不保证能验证这些界。未证明非劣时，不能只因 token 点估计改善就部署为默认策略。

决策原则：S 已获得全部收益则默认文字；F 优于 U 且优于 X、结构相关错误减少才支持按结构选图；A 才能回答拒绝／组合的整体价值。若 A 好于 F，再追加“仅允许拒绝”和“仅允许辅图”两组，分别归因；这轮不把 A 的两个变化混作单一机制。

推广阶段另选未见任务，建议状态／策略、数据契约、数学／控制、窗口／资源约束、交付流程五类各至少三个独立任务（至少 15 个任务）；这是覆盖目标而非功效计算。冻结路由规则和渲染器，按 task／family 留出，不能让同源 skill 的改名副本同时出现在开发和测试集。混合 skill 可多标签，但统计单位仍是任务。

最后再测试交付方式：固定表示后比较每轮强制重发与按需检索／初次注入。将内容选择、图型、图数量和交付频率一次全部改变，会再次失去可解释性。
